01 · 项目概述

ResumeMind 是什么

一款面向求职者的 AI 简历分析工具。用户上传简历和岗位描述，系统自动给出多维度诊断报告。

项目从零构建，涵盖前端界面、后端服务、AI 调用、数据库存储四个完整模块。作为 AGI 课程结课项目，目标是探索大模型在实际产品中的落地方式。

  • 上传 — 支持 PDF / DOCX，含扫描件 OCR
  • 分析 — 五维度诊断 + 岗位匹配度评分
  • 优化 — 简历改写 + 面试题预测 + 职业建议
  • 追踪 — 历史记录 + 标签管理 + 数据看板

02 · 项目背景

为什么要做这个项目

🔍
简历筛选是"黑箱"
求职者投递后收不到反馈，不知道简历在哪个环节被筛掉。ATS 系统的筛选逻辑对外部完全不可见。
📝
简历质量参差不齐
大多数人的简历存在结构不完整、表达空泛、缺乏量化数据等问题，但缺乏专业的诊断渠道。
💰
专业服务门槛高
职业顾问的简历修改服务费用数百至上千元，对学生和初级求职者来说成本过高。
🤖
AI 能力尚未充分落地
大语言模型多数停留在对话场景，如何将它嵌入一个完整的、可用的产品中，是一个值得探索的工程问题。
03 · 解决思路

用大模型做"简历教练"

将 HR 筛选简历的判断逻辑、ATS 系统的工作机制、面试官的提问思路——写成 AI 的 System Prompt，让大模型替代人工进行初步的简历评估与优化建议。

设计原则
用户不需要跟 AI 聊天——他们只需要上传简历 + 粘贴 JD，点一下按钮，等待一份结构化的诊断报告。底层 AI 的复杂性对用户完全透明。

05 · 功能详解

简历上传与文本提取

支持的文件类型与处理方式

📄 DOCX — 快速通道
使用 mammoth 库从内存 Buffer 直接提取纯文本。速度快（秒级完成），中文支持好，适合标准 Word 格式简历。
📸 PDF — 双路径处理
电子版 PDF：pdf2pic + Poppler 转图片 → 送视觉模型 OCR。
扫描版 PDF：同上流程，每页生成高清 PNG，逐页识别。
限 3 页 + 单页 90 秒超时，防止耗时过长。

为什么用大模型做 OCR

传统的 OCR 引擎（如 Tesseract）对中文简历的排版识别效果不佳，表格、分栏、符号列表经常识别错乱。视觉大模型不仅识别文字，还能理解版面的结构关系——段落的层级、表格的边界、列表的归属。
约束条件
文件上限 20MB；OCR 最多 3 页；超过建议改用 DOCX。这些限制在 README 和前端提示中都有说明。
06 · 功能详解

五维度智能诊断

AI 从以下五个角度对简历进行评估，每项给出 0-100 的分数 + 具体的改进建议列表。

🏗️ 结构完整性 structureScore
检查"教育经历 → 工作经历 → 项目经历 → 技能栈"这一标准链路是否完整。自动标记缺失的关键板块。
✍️ 表达质量 expressionScore
评估语句是否使用"动词 + 对象 + 结果"的专业句式，检测空泛表述和流水账式的职责罗列。
📐 量化程度 quantScore
统计简历中的数字指标——百分比、金额、团队规模、性能数据。数字比形容词更具说服力。
🤖 ATS 兼容性 atsScore
模拟招聘系统视角：章节标题是否标准？关键词密度是否足够？是否使用图片/表格阻挡了解析？
⚠️ 第五维：完整性检查 completenessScore
综合评估——列出缺失板块清单 + 风险预警项（如"工作经历信息不足""存在过于笼统的职责描述"），帮助用户快速定位简历的硬伤。
07 · 功能详解

岗位匹配引擎

AI 如何理解 JD

模型首先将 JD 中的关键词按四个类别拆分：
required
必须项（"熟悉 React"）
bonus
加分项（"开源经验优先"）
responsibilities
岗位职责关键词
seniority
资历要求

三类匹配结果

✅ 命中
简历中直接出现的关键词，加分来源
🟡 部分命中
概念相近但表述不同，改写后可转为命中
❌ 缺失
JD 要求但简历中未体现，最需要补充
🧭 不止于打分
除 0-100 的匹配度评分外，还生成针对性建议——告诉你在哪个项目描述里补上哪句话，就能命中缺失的 JD 关键词。
08 · 功能详解

简历优化与面试准备

✍️ 简历改写

❌ Before
"负责系统开发和日常维护。"
✅ After
"主导核心模块开发与维护，优化关键流程，系统稳定性提升 30%。"
AI 输出三类优化内容：rewrittenHighlights（改写原则）、beforeAfter（逐条对比）、fullDraft（完整改写稿）。核心逻辑：被动 → 主动、模糊 → 具体、过程 → 结果。

09 · 功能详解

数据看板与历史管理

📊 Dashboard 看板
五个核心指标卡片：累计分析次数、平均匹配分、平均结构分、近 7 日新增、历史最高分记录。
30 天分数趋势折线图——追踪匹配度和结构分的变化轨迹。
7 天分析次数柱状图——最直观的使用频率统计。
Top 10 缺失关键词排行榜——发现求职者的普遍短板。
📋 历史记录管理
分页列表 + 首尾页快捷跳转，支持收藏筛选、关键词搜索（文件名/岗位/内容三字段）、最低分过滤、标签筛选。
每条记录可查看完整分析详情，可删除（带二次确认）。
🏷️ 标签系统：自定义标签名 + 颜色，与记录多对多关联。按标签快速筛选同类分析——相当于一个轻量级求职 CRM。
🔀 对比功能：同时选择最多 5 条记录进行并排对比，自动标出最优版本和各维度的分数差异。

11 · 前端技术

Angular 17 项目架构

项目结构与分层

core/ ← 全局单例
  models/ — 数据模型
  services/ — API 服务
features/ ← 业务页面
  analyze/ · history/
  compare/ · dashboard/
shared/ ← 复用模块
  components/ — 通用组件
  pipes/ — 自定义管道
📦 全部 Standalone 组件
不再使用 NgModule。每个组件通过 imports 数组自行声明依赖，inject() 函数替代构造函数注入。代码量减少约一半。
🚦 路由懒加载
每个功能页面用 loadComponent 动态导入，打包时自动拆分为独立 chunk。首页加载体积最小化。
🔄 单向数据流
父组件通过 HTTP 获取数据 → 通过 @Input() 传递给子组件。数据向下流动，事件向上冒泡。无状态管理库。
12 · 前端技术

组件体系与辅助工具

💍 ScoreRingComponent
SVG 环形进度条。输入 score 和 label，通过 stroke-dashoffset 控制弧长。0 分全空、100 分满圆。圆周长 = 283（半径 45）。
📊 ResultPanelComponent
分析报告渲染容器。接收完整 AnalysisResult 对象，内部嵌入 5 个 ScoreRing + 关键词列表 + 建议清单。纯展示型组件。
🔽 CustomSelectComponent
封装下拉选择交互。输入选项列表，输出选中值。比原生 select 更好控制样式，用于分数筛选和标签筛选。
📏 ScoreColorPipe
分数 → 颜色类名：≥80 为 high（绿），≥60 为 mid（黄），其余为 low（红）。配合 CSS 变量自动着色。
🔢 KeywordCountPipe
数组 → 长度。用于在模板中直接显示"缺失关键词（5 个）"这样的统计文本。
✂️ TruncatePipe
长文本截断。用于历史列表中的 JD 描述预览，超长内容自动加省略号。
13 · 后端技术

Node.js + Express 服务架构

服务入口与中间件链

Express 应用启动 → 注册中间件 → 绑定路由 → 监听 3000 端口。
中间件顺序：cors（跨域白名单）→ express.json（1MB 限制）→ 日志中间件（打印 method + path + origin）→ 路由。
文件上传使用 multer.memoryStorage()——文件保留在内存中，不落盘，处理完即释放。

服务模块拆分

📄 ocr.service.js
封装 mammoth（DOCX）和 pdf2pic + Poppler（PDF）的文本提取逻辑。对外暴露统一的 extractResumeText(file, deps) 接口。
🧠 analysis.service.js
AI 调用核心：组装 Prompt → 发送 Ark API 请求 → JSON 解析 → 容错降级 → 输出标准化结果。
🗄️ database.js
SQLite 全部操作封装：建表、增删改查、分页、聚合统计、标签管理、score trend 查询。

15 · AI 引擎

DeepSeek 大模型集成

API 调用链路

前端 FormData → Express /api/analyze → 提取简历文本 → 组装 System + User Prompt → POST 火山引擎 Ark API → 接收 JSON 响应 → safeJsonParse 容错解析 → normalizeAnalysisResult 补全默认值 → 存入 SQLite → 返回前端渲染。
🖼️ 两个模型协同
DeepSeek-V4 文本模型：处理分析、匹配、改写、面试题生成等核心任务。
DeepSeek-V4 视觉模型：处理扫描版 PDF 的 OCR 识别——接收 base64 图片，返回提取的文字。

超时保护体系

使用 Promise.race 实现三层超时：
① AI API 调用 — 120 秒
② 单页 PDF OCR — 90 秒
③ 整体分析流程 — 180 秒
前端 Angular 侧另加 RxJS timeout(190000) 作为最后一道防线，超时后给出"建议换 DOCX 重试"的友好提示，而非无限等待。
16 · AI 引擎

Prompt 工程设计 & 容错机制

Prompt 设计策略

🎭 角色层
"你是资深 HR、ATS 筛选系统专家、技术面试官与简历优化教练"——四个角色合为一体，覆盖全部分析视角。
🔒 约束层
"必须只输出一个 JSON 对象，不要 Markdown，不要多余文字"——这是最重要的指令。System Prompt 同样强调："你只输出合法 JSON"。
📐 结构层
提供完整的 JSON Schema 示例（diagnosis / matching / optimization / interview / career 五模块），所有分数字段限定 0-100，数组限定 3-8 项。

容错降级策略

① safeJsonParse
不直接 JSON.parse。先定位第一个 { 和最后一个 }，截取中间部分再解析——模型多输出的 Markdown 前言后语被自动丢弃。
② normalizeAnalysisResult
预定义完整的 fallback 对象（所有字段都有默认值），与 AI 返回做深度合并。缺失字段自动补全，不会出现 undefined。
③ 前端防御
TypeScript 接口全部用可选字段（?），模板中大量使用可选链 ?. 和 *ngIf。即使某个字段完全缺失，UI 也不会白屏。
17 · 数据层

SQLite 数据库设计

8 张表关系图

users — 用户
job_posts — 岗位描述
resume_files — 上传的简历
analyses — 核心表（分析记录）
  ├─ structure_score
  ├─ expression_score
  ├─ quant_score
  ├─ match_score
  └─ result_json（完整 JSON）
keywords — 关键词匹配明细
tags — 自定义标签
analysis_tags — 多对多关联
💡 为什么选 SQLite
零安装、零运维。一个文件就是整个数据库，备份就是复制文件。better-sqlite3 提供同步 API——不需要 async/await，代码写起来更直观。对于课程项目和个人工具场景完全够用。
📊 数据冗余设计
analyses 表同时保存 result_json（完整分析结果）和四个数字字段（structure_score 等）。数字字段用于 SQL 排序/筛选/聚合，result_json 用于详情展示。
🏷️ 标签多对多
tags ↔ analysis_tags ↔ analyses 构成标准多对多关系。支持创建、删除标签；批量为分析记录设置标签；单个追加或移除标签；按标签筛选列表。
18 · 数据层

数据查询与可视化

动态分页查询

历史列表支持 5 种筛选条件的动态组合——收藏、搜索、最低分、标签 ID 可以任意叠加。后端通过条件拼接 WHERE 子句构建，先 COUNT 得到总条数，再 LIMIT / OFFSET 取当前页数据，一次性返回分页完整信息。

Dashboard 聚合统计

一次 Dashboard 请求在 SQLite 上同步执行 5 条查询：总分析次数 COUNT、均分 AVG、7 日新增 COUNT、最高分记录 ORDER BY LIMIT 1、缺失关键词 GROUP BY 排行。所有查询均返回原始数据，由前端负责渲染。

纯 SVG 数据图表

Dashboard 的趋势折线图和柱状图不依赖任何图表库。后端返回原始数据 → 前端 TypeScript 遍历数组算出 (x, y) 坐标 → 拼成 SVG polyline 的 points 属性直接渲染。
这样做的好处
零额外依赖、加载快、包体积小；坐标计算完全可控，不需要学习第三方库的配置项；对课程项目而言，理解原理比引入库更重要。
19 · 工程实践

错误处理与稳定性保障

🛡️
API Key 校验
启动时检查 .env 配置，缺失则 warn。请求时再次检查，无 Key 返回明确错误信息，不静默失败。
🔌
数据库降级
若 better-sqlite3 未安装，db 变量为 null。所有端点判断 if(!db) 返回合理默认值，不崩溃。
🚧
端口占用检测
监听 server.on('error')，若 EADDRINUSE，自动打印端口号和 kill 命令，而不是只报"启动失败"。
📋
前端状态管理
每个页面维护 loading / error / data 三态。加载中显示 loading 提示，出错显示具体原因，正常显示数据。
⏱️
三层超时
AI 层 120s + OCR 单页 90s + 整体流程 180s + 前端 RxJS 190s。四道防线防止长时间挂起。
📝
请求日志
每个请求记录 method + path + origin。分析与存储各阶段耗时独立输出，方便排查性能瓶颈。
20 · 开发回顾

开发过程中的关键挑战

🔥 AI 输出格式不稳定
DeepSeek 有时在 JSON 外包裹 Markdown 文本，有时漏字段。通过"System + User 双重 Prompt 约束 + safeJsonParse 容错解析 + fallback 默认值兜底"三管齐下才稳定下来。Prompt 调了不下二十版。
📄 扫描件 PDF 处理
传统 OCR 对中文简历的排版识别差。最终方案是用 DeepSeek 视觉模型"看图识字"，理解版面结构而非逐字符识别。代价是单页 30-60 秒，限制了 3 页上限。
⚡ Angular OnPush 不刷新
异步 HTTP 回调中直接修改组件属性，OnPush 检测策略下 UI 不更新。需要手动调用 ChangeDetectorRef.detectChanges() 或在关键组件使用默认策略。
🔧 Windows 环境适配
Poppler 需单独安装并加入 PATH；npm 在 Windows 上是 npm.cmd；端口占用需手动 kill。这些全写进 README 的排障指南——好的开发文档也是产品的一部分。
21 · 特色功能

简历版本对比

设计目的

用户修改简历后再次分析，两条记录可以在对比页中并排展示。量化每一次修改的进步幅度。

对比维度

• 匹配度差异（最高分的版本标注为"最优"）
• 结构分、表达分、ATS 分的各版本对比
• 共同命中关键词（多版本 Set 取交集）
• 各版本独特命中和独特缺失关键词

实现方式

URL 参数传 ids（逗号分隔，如 /compare/1,3,5），组件解析后并行发起 N 个独立 HTTP 请求获取每条分析的完整数据。最少 2 条，最多 5 条。
关键算法
getWinner() — 遍历各版本的 matchScore，找出最大值及对应版本。
getCommonMatched() — 取第一个版本的命中关键词集合，逐个检查是否在所有其他版本中均有命中。
getSummaryItems() — 逐维度计算各版本的 max - min 差值，为每个版本标注是否为最优。
22 · 总结

ResumeMind 不是一个大模型聊天应用——它把 AI 嵌入了一个完整的、可用的产品流程中。从文件上传到结构化分析报告，用户感受到的是"工具"，而非"对话框"。

💻 技术层面
完整实践了 Angular 组件化开发、Express RESTful API 设计、大模型 Prompt 工程、SQLite 数据库设计、前端数据可视化（纯 SVG 图表）、错误处理与容错体系。
🎯 产品层面
从真实痛点出发设计功能，用 AI 降低专业简历服务的门槛。六项核心功能覆盖了求职准备的全流程：投递前诊断 → 针对性优化 → 面试准备。
23 · 未来规划

后续可以扩展的方向

🔐 用户系统
JWT 登录注册，多用户数据隔离。数据库 users 表已建好，差前后端对接。这是优先级最高的需求。
🌐 多语言 + 多模型
英文简历分析支持。接入 Claude / GPT 等多模型做交叉验证——同一份简历由三个模型独立打分，结果更可信。
📱 PWA 化
Service Worker 离线缓存。可安装到桌面和手机，无网络也能查看历史分析记录。
📤 导出功能
分析报告一键导出 PDF。改写后的简历导出 DOCX。方便分享给朋友、导师或直接投递。
📊 更多可视化
五维雷达图更直观展示优劣势。关键词覆盖热力图——一目了然看到哪些能力区域是你的短板。
🐳 Docker 部署
docker-compose up 全栈一键启动。前端 Nginx 反向代理 + 后端 Node + SQLite Volume 持久化。
